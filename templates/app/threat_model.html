Threat model

STRIDE analysis of the ledger, the state machine, and the patient receipt.

Assets

AssetClassificationWhy it matters
Care event chain (per patient)Confidential · Integrity-criticalSource of truth for whether care happened
Consent recordConfidential · Integrity-criticalLegal basis for processing
Contact detailsConfidential · Special handlingEnables outreach; erasure target
Eligibility decisionConfidential · FinancialDetermines who pays
Clinical dispositionConfidential · ClinicalCloses the loop; clinical record
Session tokensHigh-value · Short-livedCompromise = full access

Actors & trust boundaries

  • Trusted: authenticated hospital / pharmacy / clinician actors, platform admin
  • Semi-trusted: patient (accesses own receipt only, phone-OTP gated)
  • Untrusted: public internet, unauthenticated requests, the payer's read-only dashboard (view-scoped)
  • Boundary 1: between the browser and the Flask app (HTTPS in prod)
  • Boundary 2: between Flask and the database (localhost / private network)
  • Boundary 3: between OneCare and external services (DHIN, Twilio) — all mocked in demo, all circuit-broken

STRIDE threats

Spoofing
ThreatMitigationResidual risk
Attacker logs in as a hospitalSession-based auth; password hashing; rate-limit on login (BUILD: hashing + session)Medium until MFA lands
Attacker calls an API with a forged actor_idSession user is authoritative; actor_id is cross-checked against session roleLow
Attacker views another patient's receiptPatient_id is unguessable UUID; OTP gate is BUILD for patient viewLow

Residual risks we accept — explicitly

  • Full-chain rewrite by DB superuser. Detected only by external anchoring. Deferred.
  • No MFA on hospital accounts. Deferred to pilot hardening.
  • No rate limiting. Deferred; documented in pilot plan.
  • Export endpoint lacks pagination. Deferred; volume is small in demo.
  • Compute runs outside Nigeria during build. Migration before pilot is a pre-requisite, not a nice-to-have.
